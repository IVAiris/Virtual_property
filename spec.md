# spec.md — исследование «Переход прав на виртуальные игровые активы» (часть IA)

## 1. Краткое описание
Операционная спецификация части IA совместного исследования по дисциплине «Интеллектуальная собственность».
Тема, предмет, гипотеза, структура и распределение работы — [research/PLAN.md](research/PLAN.md); решения — [research/DECISIONS.md](research/DECISIONS.md). Этот документ их не дублирует, а задаёт порядок получения и проверки источников и подготовки текста.

## 2. Цели
- Собрать проверенную источниковую базу для введения и разделов 1–2 (квалификация прав пользователя, договорная передача).
- Ответить по части IA на открытые вопросы Q-03 (платформы и предметы) и Q-04 (что подтверждено практикой, что — нормами и соглашениями).
- Подготовить `draft/01–03` в бюджете 8 страниц (1 + 3 + 4).
- Срок сдачи работы — 30.11.2026.

## 3. Не-цели
- Банкротство гражданина — полностью блок VP (D-02).
- Темы, исключённые PLAN.md §2 (в т.ч. ИИ — D-08).
- Исчерпывающий обзор практики: поиск ограничен описанной выборкой (PLAN.md §10).
- RAG и иная автоматизация поиска по архиву — до роста корпуса свыше ~100 документов или ~3 МБ текста.

## 4. Участники и сценарии
| Участник | Роль |
|---|---|
| IA | Автор части, согласует все изменения, ищет в ГАРАНТ и КАД, присваивает статус «проверен» |
| EDI (Claude Code) | Веб-поиск, sudact по согласованию, архив, черновые записи реестров, проверка ссылок; полномочия — CLAUDE.md |
| VP | Автор блока банкротства; точки стыка — раздел 4 и заключение |
| Преподаватель (Калятин В. О.) | Читатель итоговой работы |

Основной сценарий: вопрос → поиск → сохранение в архив → карточка в реестре → проверка → использование в главе.

## 5. Функциональные требования
1. **Проверка исходных источников** N-01–N-04, P-01. «Проверен» = зафиксирована редакция (дата) + текст соответствует тезису в колонке «Значение» + выписана точная цитата с пунктом.
2. **Поиск.**
   - Сначала с 01.01.2025; при недостаточности — ранее (D-09).
   - Источники: нормы, судебные акты, научные и аналитические статьи, профессиональные сообщества (последние — поисковый ориентир).
   - Каждый запрос — строка в SEARCH_LOG.md; отсутствие находок — по протоколу SEARCH_LOG.md.
3. **Архив.** Каждый найденный источник сохраняется в `sources/<ID>/` (оригинал + `text.md`); путь указывается в карточке. Правила публикации — `.gitignore`, `sources/README.md`.
4. **sudact** — по D-11: каждая партия запросов согласуется с IA; пауза 2 с, один поток, ≤ 30 запросов за запуск. Элементы скрипта копируются из `python-lessons` в `tools/`, исходная папка не меняется.
5. **Платформы.** Steam (P-01) + широко используемые в РФ; кандидаты согласуются с IA на шаге отбора.
6. **Маркировка** в реестрах и тексте: норма / позиция суда / условие платформы / мнение исследователя / собственный вывод — раздельно.
7. **Главы** `draft/01–03` пишутся только после отдельного согласия IA и только на источниках со статусом «проверен» или с явной пометкой гипотезы.

## 6. Нефункциональные требования
- **Достоверность:** без домыслов; каждое утверждение — источник или пометка «гипотеза / собственный вывод». Ссылка, которая открывается, не равна подтверждению тезиса.
- **Воспроизводимость:** для каждого источника — дата обращения и редакция или версия.
- **Оформление:** Times New Roman 12, интервал 1,5, стандартные поля; сноски — ГОСТ Р 7.0.5-2008, список — ГОСТ Р 7.0.100-2018; общий объём ≤ 20 страниц.
- **Приватность и право:** публичный репозиторий; статьи, соглашения и акты из КАД не публикуются; персональные данные и секреты — не в репозиторий.
- **Нагрузка на сайты:** лимиты D-11; без обхода защиты.

## 7. Технический подход
**Вариант A (выбран):** ручной поиск + локальный архив.
- EDI: веб-поиск и чтение документов по прямым ссылкам; sudact — скриптом (requests + BeautifulSoup) по согласованию; поиск по архиву — чтение целиком и grep.
- Страницы, где результаты подгружаются скриптом (поиск КиберЛенинки, sudact, соглашения платформ), — Python-скриптами на Playwright (Chromium, без окна). Скрипты — в `tools/`, окружение — `env/venv` (вне git). Запросы к sudact через браузер подчиняются D-11.
- IA: ГАРАНТ, КАД, источники за авторизацией.
- Доступ на 11.10.2026: consultant.ru (открытые статьи кодексов) — доступен, с редакцией; поиск sudact и КиберЛенинки через загрузку страницы — недоступен (результаты подгружаются скриптом); kad.arbitr — недоступен; Telegram — не подтверждено.

Обоснование: каждый тезис прослеживается до файла, максимальная достоверность при ожидаемом корпусе в десятки документов. Единственное расширение стека — Playwright (D-13); зависимости зафиксированы версиями и не публикуются.

**Вариант B (опция):** перекрёстная проверка ключевых выводов другой моделью через API (T ≤ 0,3, top-k = 4). Решение — на шаге проверки финальных выводов; требует ключа API (`.env`) и новой зависимости.

## 8. UX-потоки
- **Шаг плана:** постановка → подшаги → правила (CLAUDE.md) → поиск и анализ → проверка → обновление README (D-10).
- **Источник:** найден → текст получен → в архиве → карточка → проверен (IA) / исключён.
- **sudact:** EDI предлагает партию (запросы, число обращений) → IA согласует → запуск → строка в SEARCH_LOG.
- **Правка документа:** дифф → согласование IA → внесение.

## 9. Этапы
1. Проверка исходных источников.
2. Отбор платформ (Q-03).
3. Поиск практики (споры пользователь–пользователь и пользователь–платформа).
4. Поиск литературы.
5. Анализ соглашений платформ.
6. Итоги в реестрах, ответ на Q-04.
7. Главы `draft/01–03` (после согласия IA).
8. Сопоставление и заключение с VP; общая редактура.

Подробно, с ожидаемым результатом и фактом — Plan.md.

## 10. Критерии успеха
- Каждый существенный правовой тезис части IA — источник со статусом «проверен» или явная пометка.
- По каждому исследовательскому вопросу части IA — запись в SEARCH_LOG (включая протокол отсутствия находок).
- Q-03 и Q-04 (часть IA) закрыты в DECISIONS.md.
- `draft/01–03` ≤ 8 страниц в итоговом оформлении; пункты чек-листа draft/README.md, относящиеся к части IA, выполнены.
- Работа сдана до 30.11.2026.

## 11. Риски и компромиссы
- Практики по спорам о переходе прав на игровые предметы может быть мало → вывод строится на нормах и соглашениях с явной пометкой (PLAN.md §11).
- Поиск sudact для судов общей юрисдикции (`/regular/doc_ajax/`) не проверен; `doc_ajax` запрещён robots.txt (осознанное исключение, D-11); возможна блокировка по IP.
- Платные базы (ГАРАНТ, КАД, eLibrary) — только через IA: зависимость от её времени.
- Соглашения платформ меняются → фиксируется версия на дату обращения.
- План не согласован с VP (Q-06) → возможны изменения структуры и стыков.
- Вариант A трудоёмок; компромисс принят ради достоверности.
